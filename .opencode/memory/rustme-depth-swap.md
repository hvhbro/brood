ТЕСТ ПОДМЕНЫ DEPTH ПРОЙДЕН (2026-09-08, лог юзера): готовой depth-текстуры сцены в форке НЕТ — мир рендерится в offscreen FBO `rustme.iIlIiIiIiI` (ваниль-аналог Framebuffer, создаётся в `iilliIliiI.IiiIiilliI()` как new(fbW,fbH,true); геттер `iilliIliiI.IlliIilliI()`), depth там = RENDERBUFFER GL_DEPTH_COMPONENT24 (`illIIiIiI`), color = текстура (`iIlIIiIiI`), fb id = `lllIIiIiI`, текстурные W/H для TexImage2D = `lIlIIiIiI`/`iiilIiIiI`. Все поля public int.

Подмена из агента РАБОТАЕТ: в renderGameOverlay (главный поток) `glFramebufferTexture2D(GL_FRAMEBUFFER, GL_DEPTH_ATTACHMENT, GL_TEXTURE_2D, своя_текстура)` — renderbuffer сам отваливается; status=COMPLETE; мир пишет глубину в нашу текстуру (readback glReadPixels DEPTH_COMPONENT на IntBuffer меняется при движении камеры); игра живёт без артефактов. GL-вызовы: нативный org.lwjgl.opengl.GL30 (стаб добавлен в tools/compile_stubs + game_stubs.jar) + lwjglx GL11 (glReadPixels(IIIIIILjava/nio/IntBuffer;)V — сигнатура из дампа). Пост-FBO мода `IiIIIIiliI` color-only RGBA8, uDepth в CP нет — мод сам глубину не использует.

ГАТЧ: пересборка game_stubs.jar затирает его — собирать ВСЕГДА из 6 классов (GL20, GL30, нативный org.lwjgl.opengl.GL13, lwjglx GL11, lwjglx GL13, kotlin Function1; нативный GL13-стаб добавлен 09-08 при переводе юнитов на нативные вызовы), иначе компиляция агента валится. 09-10 в стаб lwjglx GL11 добавлены glGetTexImage(IIIIILjava/nio/FloatBuffer;)V и GL_ONE=1 (для JumpDistort depth-копии/аддитивного кольца); пересборка: javac -encoding UTF-8 -d tools/stubs_build tools/compile_stubs/org/lwjglx/opengl/GL11.java → jar uf tools/game_stubs.jar -C tools/stubs_build org/lwjglx/opengl/GL11.class. DepthTest-модуль (toggle B) УДАЛЁН 08-08 при реализации WetWorld — механика подмены вынесена в `utils/etc/DepthSwap.java` (ensure идемпотентен, переживает ресайз, детект пересоздания FBO по id/размеру/colorTex) — ОБЩАЯ для WetWorld (SSR) и SkyNebula (небо), см. [[rustme-wet-world-shader]].

Следствие: шейдеры wet_world/rain_screen из rockstar-client-src (SSR-мокрые блоки + капли, depth-based) портируемы. Нужно для порта: инверсия MV/PROJ на CPU (InvViewProj), CamPos из статиков IlIIliiIiI, Time, полноэкранный ортоквад с нашей GLSL-программой в начале iliIiiIliI (до super — depth цел), ресайз-обработка (пересоздание FBO обнуляет подмену). УРОКИ ПЕРВОГО ПРОГОНА ПОСТ-ПРОХОДОВ (09-08, тест WetWorld/SkyNebula провален и починен):
1. Color-текстура игры (`iIlIIiIiI`) В МОМЕНТ OVERLAY ПУСТАЯ (пост-цепочка мода её переиспользует) — сцену для пост-проходов брать glCopyTexSubImage2D из ТЕКУЩЕГО read-буфера (куда рисуют игра+ESP — доказанно видимый), не сэмплингом игровой текстуры. Проверено readback'ом: `scene copy check mean=34` (тёмная сцена, но не 0).
2. Сэмплировать depth (или любую текстуру), АТТАЧНУТУЮ к целевому FBO = feedback loop = поведение undefined, драйвер МОЛЧА пропускает рисование. РЕШЕНИЕ ФИНАЛЬНОЕ: небо рисуется в СВОЙ postFbo БЕЗ depth-аттачмента → depth-текстуру DepthSwap можно сэмплировать НАПРЯМУЮ (полная 24-бит точность); alpha-маска `step(0.99999, depth)` + blend-блит. (Промежуточный вариант «копия depth в 8-бит цвет» ОТМЕНЁН: RGBA8 квантует — всё дальше ~23м превращалось в «небо». PostRig.depthToColor остался в коде неиспользуемым.)
3. glGetInteger(GL_VIEWPORT, IntBuffer) через lwjglx-шим ненадёжен (семейство glGetFloat-гатча) — физ. размер сцены брать из DepthSwap.texW/H.
4. КАМЕРА-ОТНОСИТЕЛЬНОЕ ПРОСТРАНСТВО (главное): шейдеры rockstar ждут ViewProj БЕЗ трансляции (view = вектор из камеры, world = CamPos + view в шейдере) — с полной view-матрицей SSR не бьёт, normalize(farPoint) ≈ константа. VIEW = только вращение (yaw+180/pitch).
5. Захваченная PROJ мода: m10=-1.0004113, m14=-0.100020565 → FAR ≈ 243м КОНЕЧНЫЙ (не бесконечный, как считали в ESP-заметках), near=0.05. Геометрия за far даёт depth=1.0 = неотличима от неба.
6. ПЕРЕКЛЮЧЕНИЕ ТЕКСТУРНЫХ ЮНИТОВ — подозреваемый №1 при «сэмплер молча читает 0»: lwjglx-шимп GL13.glActiveTexture может быть no-op для юнита≠0 (шим с мёртвыми функциями — прецеденты glGetFloat/glTexCoord2f). Симптом-подпись: один сэмплер жив (bind на юнит по умолчанию), второй читает 0. ВСЕГДА переключать юниты НАТИВНЫМ org.lwjgl.opengl.GL13; самотест — PostRig UNIT TEST (glGetInteger(GL_ACTIVE_TEXTURE) после переключения). MSDF не ловил гатч — ей нужен только юнит 0.
7. GL_CURRENT_PROGRAM = 0x8B8D (0x8B8E не существует как pname → 1280 Invalid enum + glGetInteger вернёт 0). Спам «GL ERROR 1280 @ Post render» в логе игры = наш glGetInteger с неверным enum.
8. Диагностическая сборка 09-08 (5-я итерация): DEBUG_VISUAL в WetWorld/SkyNebula рисует R=depth/G=маска/B=discontinuity или dir.y на весь экран — по одному скрину разделяет «сэмплер мёртв» vs «матрицы/эффект»; PostRig.logTexStats (readback через временный FBO-аттачмент — glReadPixels читает FBO, не текстуру!) и logGlError (glGetError в стаб lwjglx GL11 добавлен). soyuz-master — C++ клиент с нативными хуками glClearColor/glFogfv (путь запрещён), подтверждает fixed-function GL рендера; его модули — источник идей.
